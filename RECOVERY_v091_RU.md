## Что сохраняется

Данные остаются в `/content/drive/MyDrive/EntoKey/Foundation_v06`.
Сохранённый отбор находится в `raw/bioscan/diptera_added_families_topup_selection.csv`.
Его наличие означает, что отбор закончен, но не доказывает, что JPEG скачаны.

`checkpoint` делает проверенные SHA-256 резервные копии манифеста, отбора и отчётов
в `recovery_backups` рядом с оригиналами. Изображения и большой metadata CSV не
копируются. Контрольная точка фиксируется в `poc_v09/bioscan_recovery_checkpoint.json`.

`bioscan-topup` проверяет сохранённый отбор и переиспользует совместимые legacy
CSV + JSON без повторного сканирования metadata. Проверяются существующие JPEG,
докачиваются недостающие. При прерывании сохраняются уже записанные изображения.
Манифест публикуется после успешного завершения; все прежние specimen IDs сохраняются.
Если сохранённый отбор повреждён/неполон, он не заменяется автоматически.

## Источники

- iNaturalist PoC: ограниченная выборка из официального dataset
  `50c9509d-22c7-4a22-a47d-8c48425ef4a7` через GBIF API. Source остаётся iNaturalist;
  сохраняются исходные observation ID, ссылки, лицензии фото и авторство. Это не
  полная репрезентативная выгрузка iNaturalist; данные отражают публикацию в GBIF.
- GBIF PoC: отдельная ограниченная выборка `PRESERVED_SPECIMEN` с разрешённой
  лицензией изображения. По одному фото на экземпляр, квоты по целевым семействам.
- Поддерживается старый путь с уже имеющимися официальными bulk-таблицами и DWCA.
  Мировой iNaturalist-архив теперь требует явного `--allow-bulk-download`.
- DiSSCo: точный order=Diptera, livingOrPreserved=Preserved, hasMedia=true,
  basisOfRecord=PreservedSpecimen. Исправлены resume после сохранённой страницы,
  обработка /full и выбор реального accessURI вместо DOI-страницы.
- Квоты 30k/30k/25k/15k — цели, не гарантия доступности. Число изображений после
  фильтрации/дедупликации может быть меньше 100k. Источники не подменяются.

## Запуск

Используйте исправленный notebook. Одновременно — только одна активная сессия
загрузки в эту папку Drive. Ячейки запускаются по очереди, не через Run all.
Первые этапы: настройка → doctor → checkpoint → bioscan-topup. Здесь можно остановиться.
Далее отдельные загрузки iNaturalist, GBIF, DiSSCo → ingest → assemble → plan → cache
→ quality. `quality` обязательно выполняется до embeddings и требует GPU: OWLv2 проверяет
музейные GBIF/DiSSCo изображения на наличие и масштаб мухи. Очевидные обзоры,
этикетки и слишком мелкие экземпляры помещаются в отдельный review-манифест.
Достаточно детальные экземпляры с лишним фоном обрезаются в отдельную derived-папку.
Исходный кэш не изменяется; checkpoints позволяют продолжить после отключения.
Доступ к DINOv3 нужен только для embeddings. BioCLIP загружается отдельно через
`open_clip_torch`. Оба encoder используют уже сохранённый cache; фотографии повторно не
скачиваются. Обучение по умолчанию выключено.

Пустой/недостающий вход останавливает ingest до изменения корпусных файлов.
ManifestWriter публикует CSV/Parquet атомарно по успешному завершению; прерванная
запись не заменяет предыдущий файл. Неполный training plan не публикуется.

экземплярах, crops, resume без повторного inference и ручных overrides.

но не заменяют полный запуск на пользовательском Drive и оценку модели.
